# VB6 Application to ASP.NET Core Blazor Server Migration

## Objective
Transform VB6 desktop applications with forms, ADO database connectivity, and SQLite backends into modern ASP.NET Core Blazor Server web applications targeting .NET 10, leveraging Entity Framework Core, ASP.NET Core Identity for authentication, and implementing clean architecture patterns with dependency injection while adhering to organizational coding standards.

## Summary
This transformation modernizes a legacy VB6 desktop application by converting MDI containers and forms to Blazor components with MainLayout and individual pages, replacing ADO data controls and data binding with Entity Framework Core async operations using IDbContextFactory for thread safety, migrating VB6 modules (.bas files) to C# services and extension methods with primary constructors, transforming VB6 controls including MSFlexGrid, ListView, Toolbar, and Control Arrays to HTML tables and Blazor UI components with data binding, converting form-based authentication to ASP.NET Core Identity with cookie authentication, implementing IAuditable interface on all entity classes for audit trail requirements, applying modern C# features including file-scoped namespaces, records for DTOs, collection expressions, pattern matching, and target-typed new expressions, and organizing the solution using the prescribed project structure with /Pages, /Components, /Models, /Services, /Data, and /Extensions folders.

## Entry Criteria
1. The codebase must be a VB6 application with .frm form files, .bas module files, and a .vbp project file
2. The application must use ADO (ADODB.Connection, ADODB.Recordset) for database connectivity with either direct SQL queries or ADODC data-bound controls
3. The application must have a main form (MDI container or standard form) that serves as the primary navigation entry point and can be converted to a web layout
4. The database must be SQLite accessible via ODBC connection string, with the database file path identifiable in the connection string
5. The VB6 forms must use standard controls (TextBox, ComboBox, ListView, MSFlexGrid, CommandButton, Toolbar, ImageList) that have direct or indirect equivalents in HTML/Blazor
6. The application must have identifiable business logic in either form code-behind, module functions, or event handlers that can be extracted into service classes
7. All database table schemas must be accessible so Entity Framework Core entity models can be generated from the SQLite database
8. The transformation target must be ASP.NET Core 10.0 with Blazor Server and Entity Framework Core 10.0 with SQLite provider
9. All developers must follow the organization's coding standards including file-scoped namespaces, records for DTOs, primary constructors, and structured logging with correlation IDs

## Implementation Steps

1. **Analyze VB6 Application Structure**: Inventory all .frm form files, .bas module files, and identify the main form or MDI container; catalog all database tables by examining SQL queries in the codebase and the SQLite database schema; identify all VB6 controls used (MSFlexGrid, ListView, ADODC, Toolbar, ImageList, Control Arrays); map each form's purpose to determine corresponding Blazor page names; document all module functions across .bas files for conversion planning.

2. **Create ASP.NET Core Blazor Server Project**: Create a new ASP.NET Core Blazor Server project targeting .NET 10.0; add NuGet packages for Microsoft.EntityFrameworkCore (10.0), Microsoft.EntityFrameworkCore.Sqlite (10.0), Microsoft.AspNetCore.Identity.EntityFrameworkCore (10.0); configure connection string in appsettings.json pointing to the existing SQLite database file; establish project folder structure with /Pages, /Components, /Models, /Services, /Data, and /Extensions directories per organizational standards.

3. **Generate Entity Framework Core Models**: Use Entity Framework Core database-first approach to scaffold DbContext and entity classes from the existing SQLite database using the command "dotnet ef dbcontext scaffold"; apply organizational naming conventions by converting VB6 Hungarian notation (strCustomerName, intCount) to PascalCase (CustomerName, Count); implement IAuditable interface on all entity classes with CreatedDate, CreatedBy, ModifiedDate, ModifiedBy properties; convert VB6 integer status codes to strongly-typed enums with extension methods for legacy compatibility; use DateOnly type for date fields without time components; create DTO records using modern C# syntax: public record EntityDto(int Id, string Name, string Description);.

4. **Configure Entity Framework Core DbContext**: Create an application DbContext class inheriting from DbContext with file-scoped namespace; register DbContext using IDbContextFactory in Program.cs for Blazor Server thread safety; implement SaveChangesAsync override to automatically populate IAuditable properties (CreatedDate, CreatedBy, ModifiedDate, ModifiedBy) before saving; configure SQLite-specific options including foreign key constraints and query optimizations; add structured logging using ILogger with correlation IDs in all database operations; wrap all database calls in try-catch blocks with DbUpdateException handling per organizational error handling standards.

5. **Migrate VB6 Modules to C# Services and Extensions**: Convert connection-related .bas module functions (connection opening, SQL execution) to a DatabaseService class registered in DI container with async methods (ExecuteQueryAsync, ExecuteCommandAsync); transform utility .bas module functions (formatting, validation helpers) to extension method classes organized by domain in /Extensions folder; convert .bas module global variables (user context, application state) to service interfaces and implementations using HttpContext or authentication claims; migrate logging functions to structured logging using ILogger<T> with correlation ID tracking; use primary constructors for all service classes: public class EntityService(AppDbContext db, ILogger<EntityService> logger).

6. **Transform Main Form to Blazor MainLayout**: Convert the main form or MDI container to MainLayout.razor component; transform VB6 menu structures to NavMenu.razor component with navigation links using <NavLink>; replace VB6 StatusBar controls with Blazor status bar components bound to application state; implement @Body placeholder in MainLayout.razor for rendering child page components; convert VB6 menu click handlers to NavigationManager.NavigateTo calls; apply responsive design patterns to support various screen sizes unlike the fixed VB6 desktop interface.

7. **Convert VB6 Forms to Blazor Pages**: For each VB6 .frm file, create a corresponding .razor page component in /Pages directory using a descriptive naming convention (e.g., frmCustomers.frm becomes Customers.razor); replace VB6 Form_Load event with Blazor @code { protected override async Task OnInitializedAsync() }; convert VB6 ADODC data-bound TextBox controls (DataField, DataSource) to Blazor @bind directives (<InputText @bind-Value="entity.PropertyName" />); transform VB6 MSFlexGrid controls to HTML <table> elements with Blazor @foreach loops for data binding; convert VB6 Toolbar controls (Add, Edit, Save, Delete, Search, Cancel buttons) to Blazor <button> elements with @onclick event handlers; replace VB6 ListView controls with HTML tables or Blazor component libraries; eliminate VB6 Control Arrays by using Blazor @for loops or component parameterization.

8. **Implement Authentication Migration**: If the VB6 application has a login form or authentication logic, convert it to a Login.razor page component in /Pages directory; replace VB6 SQL-based authentication with ASP.NET Core Identity using IdentityUser and UserManager<IdentityUser>; configure cookie authentication in Program.cs using builder.Services.AddAuthentication(CookieAuthenticationDefaults.AuthenticationScheme); hash all passwords using Identity's PasswordHasher instead of storing plain text; migrate user roles from VB6 user level fields to ASP.NET Core Identity roles using RoleManager<IdentityRole>; implement [Authorize] attributes on Blazor pages requiring authentication with role-based access control; store user context information in authentication claims accessible via AuthenticationStateProvider.

9. **Transform VB6 Error Handling to Structured Exception Handling**: Replace all VB6 "On Error GoTo ErrorHandler" patterns with C# try-catch blocks using specific exception types (DbUpdateException, InvalidOperationException, ArgumentException); convert VB6 MsgBox error displays to Blazor toast notifications or modal dialogs using component libraries; implement structured logging using ILogger<T> with log levels (LogError, LogWarning, LogInformation) and correlation IDs; wrap all async database operations in try-catch blocks per organizational standards; create custom exception classes for domain-specific errors; implement global exception handling using ErrorBoundary components in Blazor.

10. **Migrate VB6 Data Validation to C# Validation**: Convert VB6 validation functions (text emptiness checks, numeric validation, format validation) to C# data annotation attributes ([Required], [Range], [RegularExpression]) on DTO record properties; implement IValidatableObject interface on complex DTOs requiring custom validation logic; replace VB6 client-side validation with Blazor EditForm component using <DataAnnotationsValidator /> and <ValidationSummary />; add server-side validation in service layer methods before database operations; display validation errors using <ValidationMessage For="@(() => model.PropertyName)" /> in Blazor components; ensure async validation methods where necessary.

11. **Convert VB6 Date Handling to Modern C# Patterns**: Replace VB6 Date type with C# DateOnly for dates without time components per organizational standards; convert VB6 date formatting (Format(Date, "mm/dd/yyyy")) to C# string interpolation with format specifiers: $"{date:MM/dd/yyyy}"; transform legacy VB6 date strings using DateTime.ParseExact with CultureInfo.InvariantCulture; use DateTimeOffset for timestamps requiring timezone awareness; implement date range validation using [Range] attributes with DateOnly boundaries; convert VB6 Now function calls to DateTime.UtcNow or DateTimeOffset.UtcNow to avoid timezone issues.

12. **Transform Business Logic to Service Layer**: Extract business logic from VB6 form event handlers (Toolbar button clicks, command button clicks) into dedicated service classes in /Services directory organized by domain; implement repository pattern if complex data access logic exists, otherwise use DbContext directly in services; register all services in Program.cs DI container using appropriate lifetimes (builder.Services.AddScoped<IService, ServiceImplementation>); convert synchronous VB6 database operations (rs.Open, rs.AddNew, rs.Update) to async C# methods; implement transactional logic using DbContext transactions for multi-step operations (await using var transaction = await _dbContext.Database.BeginTransactionAsync()); apply organizational business rules including audit trail population and correlation ID tracking.

13. **Migrate VB6 Search and Filtering Logic**: Convert VB6 search forms or search functions to Blazor search components with dynamic filtering; replace VB6 SQL string concatenation for WHERE clauses with LINQ Where clauses or EF Core IQueryable filtering; transform VB6 LIKE queries to EF Core .Where(x => x.Property.StartsWith(value)) or .Contains(value); implement debounced search input using Blazor @oninput events with Task.Delay to avoid excessive database queries; add pagination for large result sets using Skip() and Take() or component library pagination controls; ensure all queries are async using ToListAsync(), FirstOrDefaultAsync().

14. **Convert VB6 ComboBox and Lookup Data**: Replace VB6 ComboBox loading functions with Blazor <select> elements or <InputSelect> components bound to entity collections; load lookup data in OnInitializedAsync using async service methods; bind dropdown options using @foreach or collection binding; convert VB6 ComboBox.ItemData pattern (storing IDs separate from display text) to object binding in Blazor <InputSelect> with @bind-Value; implement cascading dropdowns using Blazor @onchange events that reload dependent dropdowns; cache frequently accessed lookup data using IMemoryCache to reduce database queries.

15. **Transform Record ID Generation Logic**: Convert VB6 custom ID generation functions (sequential IDs with identifiers and date suffixes) to database auto-increment identity columns or GUID primary keys; if custom ID formats are required, implement as computed columns or generate in service layer before insert; ensure thread-safe ID generation using database sequences or lock mechanisms if not using auto-increment; update all foreign key relationships to match new primary key types; migrate any existing data preserving original IDs during initial database migration.

16. **Implement Modern C# Coding Standards**: Apply file-scoped namespaces to all C# files (namespace App.Services; without braces); use collection expressions throughout: List<Entity> items = []; use target-typed new for object instantiation: Entity entity = new(); apply null-coalescing assignment operators: _cache ??= LoadCache(); use pattern matching for conditionals instead of if/else chains (switch expressions with when clauses); replace VB6 string concatenation with C# string interpolation; use primary constructors for dependency injection in services and components; ensure async suffix on all async methods per organizational standards (GetEntityAsync, SaveEntityAsync).

17. **Configure Blazor Server State Management**: Implement scoped services for managing UI state across Blazor components that need to share data; use Blazor parameter binding with [Parameter] attributes for parent-child component communication; implement INotifyPropertyChanged or EventCallback<T> for reactive UI updates when data changes; store user-specific session state using scoped services registered with builder.Services.AddScoped<TService>(); avoid singleton services for user-specific data to prevent cross-user data leakage in Blazor Server; implement cascading parameters for deeply nested component hierarchies requiring shared context.

18. **Migrate VB6 Report and Export Features**: If the VB6 application has reporting features (Print statements, Crystal Reports, export to Excel), convert to modern reporting libraries like FastReport, Telerik Reporting, or generate Excel files using EPPlus or ClosedXML; transform VB6 print preview forms to PDF generation using libraries like QuestPDF or DinkToPDF; implement export functionality as downloadable files using Blazor JSInterop for triggering browser downloads; convert any VB6 report layouts to HTML/CSS templates with Blazor data binding for dynamic content rendering.

19. **Test End-to-End Functionality**: Create integration tests for each migrated form's CRUD operations using WebApplicationFactory and bUnit for Blazor component testing; validate that all VB6 business logic has been correctly migrated by comparing outputs from identical inputs; test authentication flows including login, role-based access, and session management if applicable; verify audit trail functionality (IAuditable properties) is populating correctly on all entity operations; performance test async database operations to ensure responsiveness; test cross-browser compatibility (Chrome, Firefox, Edge, Safari) since Blazor Server is now web-based; validate mobile responsiveness if required by business needs.

20. **Deploy and Cutover Planning**: Configure production environment with Kestrel or IIS hosting for ASP.NET Core 10.0; ensure SQLite database file is deployed and accessible with appropriate file permissions; configure connection string secrets using Azure Key Vault, AWS Secrets Manager, or environment variables instead of appsettings.json for production; implement database migration scripts if schema changes were made during transformation; plan user training for transition from desktop interface to web-based Blazor interface; establish rollback plan with VB6 application backup; implement monitoring using Application Insights or similar for error tracking and performance metrics; migrate all user accounts to ASP.NET Core Identity with password reset requirements if authentication was present in the original application.

## Validation / Exit Criteria

1. All VB6 forms from the source application have corresponding Blazor page components in the /Pages directory with equivalent functionality for viewing, adding, editing, and deleting records
2. The main form or MDI container structure has been successfully converted to MainLayout.razor with a NavMenu component that provides navigation to all application features
3. All database operations have been migrated from ADO/ADODC to Entity Framework Core with async methods (ToListAsync, FirstOrDefaultAsync, SaveChangesAsync) and are using IDbContextFactory for thread safety
4. All entity classes implement the IAuditable interface with CreatedDate, CreatedBy, ModifiedDate, ModifiedBy properties that automatically populate during save operations
5. If authentication existed in the VB6 application, it has been migrated to ASP.NET Core Identity with cookie authentication, password hashing, and role-based authorization using [Authorize] attributes
6. All VB6 module functions from .bas files have been converted to C# services or extension methods organized in appropriate directories
7. All C# code follows organizational coding standards including file-scoped namespaces, records for DTOs, primary constructors, collection expressions, pattern matching, and target-typed new
8. All error handling uses structured exception handling with try-catch blocks, specific exception types, and ILogger with correlation IDs instead of VB6 "On Error GoTo" patterns
9. All validation logic uses data annotations, IValidatableObject, or explicit service-layer validation instead of VB6 validation functions, with errors displayed using Blazor ValidationMessage components
10. The application successfully connects to the SQLite database, and all CRUD operations produce correct results matching VB6 behavior
11. Integration tests pass for all major workflows covering the core business operations of the application
12. The application runs without errors in Blazor Server mode, handles concurrent users appropriately with scoped services, and provides responsive UI updates using Blazor data binding
13. All lookup data (ComboBox sources) loads correctly using async methods and displays in Blazor select components or dropdown alternatives
14. Search and filtering functionality works correctly using LINQ queries and EF Core IQueryable filtering, returning results matching VB6 search behavior
15. The application successfully deploys to the target environment (IIS, Kestrel, or cloud platform) and is accessible to users via web browsers with authentication enforced on protected pages if applicable
