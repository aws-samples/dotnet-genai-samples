Deployment 1: Developer machine or Amazon EC2 (Windows Server)

One Amazon CloudWatch agent per host: OTLP for traces and metrics, file tailing for Serilog logs

Overview · Deployment 1: Laptop / EC2 · Deployment 2: Amazon ECS on AWS Fargate

Architecture

Traces (OTLP)Metrics (OTLP)Logs (Serilog → JSON file → agent tails)

Talk track

  1. Traces and metrics: the OpenTelemetry .NET SDK exports over OTLP to the CloudWatch agent on the same host.
  2. Logs: application code logs through the standard ILogger. Serilog adds the current trace ID and span ID to each entry and writes one JSON object per line to a rolling log file.
  3. Agent: one CloudWatch agent per host receives OTLP and tails the log files. One config file covers all three signals.
  4. Delivery: the agent sends traces to AWS X-Ray, metrics to CloudWatch Metrics, and logs to CloudWatch Logs, using the instance role on EC2.
  5. Correlation: the trace ID in every log line links logs to the trace in CloudWatch.

Why this design

  • Laptop to EC2 with no code changes: the same agent and config pattern runs on a developer machine and on Amazon EC2.
  • Durable logs: files on disk survive a brief agent restart; the agent resumes tailing where it left off.
  • Familiar operations: Windows teams manage the agent like any other service, and AWS Systems Manager can roll it out across a fleet.
  • Option: for a fully OTLP pipeline, customers can also evaluate sending logs over OTLP to the AWS Distro for OpenTelemetry (ADOT) collector.
